## 0. 요약 (TL;DR)

- **현 위치**: 1인 개발로 채팅·음성·칸반·크론·프로필관리·멀티에이전트 토론까지 **PC 대시보드 기능 대부분을 네이티브로 이식**한 상태. Phase 14(Deep think)까지 실기기 검증 완료, Phase 15~20은 코드는 있으나 **맥 빌드/실기기 미검증(NEEDS-BUILD)**.
- **가장 큰 강점**: 게이트웨이 공식 API 직결 + Bridge 보완이라는 **검증된 아키텍처**, SSE 미전송 실기기 버그를 폴링으로 우회한 **현장 견고성**, SPM 의존성 0(자체 마크다운/음성 파서)으로 **심사·유지보수 리스크 최소화**.
- **가장 큰 공백**: ① Phase 15~20 **미검증 부채**(음성 핸즈프리·글라스·크론·프로필생성), ② **실시간 푸시 부재**(로컬 폴링·BGAppRefresh만 — 백그라운드 즉시성 없음), ③ PC엔 있는 **에이전트 비동기 실행(`/v1/runs`)·터미널·파일 편집** 미노출.
- **모바일 차별화 최대 기회**: **Live Activity(다이내믹 아일랜드)** — 실행 중 칸반·토론·긴 응답·음성 대화 상태를 잠금화면에 라이브 표시. 모바일만 가능하고 "PC보다 나은" 가장 명확한 카드.

## 2. 강점 분석

1. **검증된 아키텍처 (환각 없는 설계)** — PLAN §0가 hermes-agent 소스/문서에서 확인한 사실(프로필=독립 포트, 게이트웨이 API 목록, Bridge가 메우는 공백)에만 근거. "세션/대화는 항상 게이트웨이 직결, 못 하는 것만 Bridge"라는 단일 원칙이 일관됨.
2. **현장 견고성** — 실기기에서 게이트웨이가 세션엔 기록하나 SSE로는 안 흘리는 버그를 **폴링 폴백(T-114/116/121)**으로 우회. 이론이 아니라 실기기 증상에서 나온 방어 코드. 네트워크 실패는 알럿 남발 대신 placeholder/읽기전용 강등.
3. **의존성 0 정책의 이점** — SPM 패키지 0, 자체 마크다운(`MarkdownLite`)·음성·이미지 파이프라인. → **App Store 심사에서 서드파티 SDK 추적·개인정보 문제 없음**, 멀티에이전트 pbxproj 수동편집 구조에서 파손 위험 제거.
4. **프라이버시 우위** — 전 통신이 Tailscale 사설망 안. 공인망 노출/클라우드 저장 없음 → 심사 시 데이터 수집 라벨이 매우 깨끗.
5. **PC 패리티의 폭** — 칸반·크론·프로필생성·모델선택·토론까지 모바일에서 네이티브로 — 단순 채팅 클라이언트를 넘어선 **운영 콘솔** 수준.
6. **문서 규율** — 3-문서 단일원본 + 태스크 ID 추적 + 빌드검증 기록. 교대 개발에 강함.

## 3. 부족한 점 / 리스크

### 3.1 제품 부채

- **미검증 부채가 큼(Phase 15~20)**: 가장 "모바일다운" 기능들(핸즈프리 음성·글라스·Siri 진입)이 전부 NEEDS-BUILD. 코드 양은 많은데 실기기 통과가 없어 **출시 가치로 환산되지 않은 상태**.
- **실시간성 한계**: 푸시가 없다. 로컬 폴링(포그라운드 60초) + BGAppRefresh(iOS가 실행시점 미보장)뿐 → 칸반 완료·크론 결과·긴 응답을 **앱이 꺼져 있으면 제때 못 받음**. 백그라운드 에이전트(칸반 디스패처)와 모바일 알림의 간극이 큼.
- **에이전트 실행 가시성 부족**: 채팅 단위만 보임. 칸반 running 태스크나 비동기 run의 **진행 로그/스트림을 실시간으로 들여다보는 화면이 없음**(완료 후 알림만).
- **읽기전용 영역**: 툴셋 토글(T-098), Bridge config 편집(T-097)이 미구현 — 설정 일부가 보기만 됨.
- **첨부 = 경로 prepend 방식의 한계**: 게이트웨이 chat이 텍스트 전용이라 파일경로를 본문에 끼워 보냄. 비전 품질은 백엔드 모델·HEIC 처리(T-130 미검증)에 의존.

### 3.2 App Store 심사 리스크 (현재 심사 중 — 중요)

| 항목 | 리스크 | 권장 |
|---|---|---|
| **로컬 서버 의존(Tailscale)** | 심사자가 사설 서버에 접속 불가 → "기능을 시연할 수 없음"으로 거절 가능(가장 흔한 사유) | **데모 모드/스크린샷 또는 심사용 데모 서버 + 리뷰노트에 접속법 명시** 필수 |
| **백그라운드 audio**(T-120) | 잠금화면·주머니 음성유지를 위해 `UIBackgroundModes: audio` 선언 → 실제 지속 오디오 사용 근거가 약하면 리젝 | 핸즈프리 대화가 *실제로* 백그라운드 오디오를 쓰는 흐름임을 리뷰노트로 설명 |
| **전체 사진 접근**(T-125) | 글라스 사진 감지에 전체 접근 필요 → 목적 설명 부족 시 지적 | `NSPhotoLibraryUsageDescription`에 "글라스 촬영 자동 전송" 목적 명확화(T-128에 반영됨) |
| **마이크 상시 표시등** | 핸즈프리 중 점등 → 의도된 동작이나 사용자 혼란 | 앱 내 안내 |
| **앱 완성도** | NEEDS-BUILD 기능이 UI엔 보이는데 서버 미배포 시 404 → 심사자에겐 "버그" | 심사 빌드에선 미검증 기능 **숨김/비활성** 권장 |

> 핵심: 심사 거절의 1순위는 기능 결함이 아니라 **"심사자가 사설망 백엔드에 닿지 못해 시연 불가"**일 가능성이 높음. 리뷰노트·데모계정·데모영상이 코드보다 중요.

## 4. PC(hermes-agent·대시보드)엔 있으나 모바일에 없는 기능

> 근거: PLAN §0.2 게이트웨이 API + §0.3 Bridge 공백 + 대시보드(:8000) 기능.

| # | PC에 있음 | 모바일 현황 | 강화 방안 |
|---|---|---|---|
| 1 | **비동기 에이전트 실행** `POST /v1/runs` + `GET /v1/runs/{id}/events` | **미노출** (채팅 스트림만 사용) | 장시간 에이전트 작업을 "실행"으로 띄우고 이벤트 SSE를 진행화면으로. Live Activity와 결합 시 모바일이 더 우월 |
| 2 | **터미널 / 명령 실행** | WebView 임베드(T-060)만, 네이티브 없음 | 보안상 네이티브 exec는 의도적 제외(PLAN §Phase7) — **유지 권장**. 대신 "채팅으로 명령 시키기" UX 다듬기 |
| 3 | **파일 편집** | 파일 브라우저 **읽기전용**(T-061) | Bridge `PUT /files`(HERMES_HOME 제한 + .bak) 추가 → SOUL.md 외 일반 파일도 편집 |
| 4 | **로그 실시간 tail** | 프로필 로그 조회(정적) | `GET /logs?tail=&follow` 폴링/스트림 → 라이브 로그 뷰 |
| 5 | **툴셋 on/off** | 조회만(T-098 미구현) | T-097/098 완성 — 토글→Bridge PATCH→재시작 |
| 6 | **칸반 events 타임라인** | done/blocked diff 폴링만 | T-096 events 증분 → 태스크별 진행 타임라인 |
| 7 | 대시보드의 통계/대시 위젯 | WebView로 우회 | 네이티브 카드(헬스·세션수·실행중 태스크)로 홈 보강 |

→ **결론**: PC 우위 항목 중 모바일이 따라갈 가치가 큰 것은 **①비동기 실행 가시화, ④라이브 로그, ⑤툴셋 토글**. 터미널/exec는 보안 철학상 의도적 비도입 유지가 옳음.

## 5. 모바일이기에 "더 나은" 기능 (핵심 차별화)

### 5.1 Live Activity / 다이내믹 아일랜드 ★최우선 추천

PC엔 없고 모바일만 가능한 가장 강한 카드. 잠금화면·다이내믹 아일랜드에 라이브 표시:
- **실행 중 칸반 태스크** — 디스패처가 워커 실행 중인 태스크의 상태/경과.
- **Deep think 토론 진행** — "3명 발언 중 · 라운드 2/3".
- **긴 채팅 응답 생성 중** — 토큰 스트리밍 상태(앱 나가도 보임).
- **핸즈프리 음성 대화** — 듣는 중/말하는 중/처리 중.

구현: `ActivityKit`(내장, SPM 불필요). 업데이트는 ① 앱 포그라운드 직접 갱신, ② 백그라운드는 APNs `liveactivity` 푸시(아래 5.6과 묶음). **심사 친화적**(표준 API, 명확한 사용자가치).

### 5.2 AirPods 강화

현재(T-119): AVRCP 미디어키로 스템탭=시작/전송/바지-인. 그 위에:
- **AirPods Pro 2 머리 제스처** — 끄덕임=전송/수락, 가로저음=취소/건너뛰기. TTS 답변 "들으시겠어요?"에 손 안 대고 응답. (iOS 17.2+ 제스처 API)
- **자동 귀 감지 연동** — 에어팟을 빼면 음성루프 일시정지, 다시 끼면 재개(현재 라우트 분리 옵저버 T-117 확장).
- **개인화 공간음향 TTS** — 답변 낭독을 공간음향으로 → "옆에서 비서가 말하는" 몰입감.
- **Siri 알림 읽어주기** — 칸반/크론 완료 알림을 에어팟으로 자동 낭독(announce notifications 카테고리).

### 5.3 Ray-Ban Meta 글라스

현재 한계는 명확히 조사됨(Meta DAT가 3P에 탭/카메라 미제공 — Phase 16/17 주석). 그 제약 안에서:
- **현행 경로 검증 우선**(사진 보관함 감시 + AVRCP 탭 + Siri/URL 진입) — 신규 SDK 없이 가능, 심사 안전.
- 추가 여지: 글라스로 들은 답변을 **문장단위 저지연 스트리밍 TTS**로 더 자연스럽게(T-118 핵심), "사진 도착" 같은 **상황 음성 알림**의 카피/타이밍 튜닝.
- Meta DAT 카메라 스트림은 개발자 프리뷰라 **미도입 결정 유지**(사용자 결정·심사 리스크).

### 5.4 카메라 라이브 — "보면서 묻기"

글라스 없이도 모바일 강점: **카메라를 켜고 프레임을 캡처→즉시 음성으로 질문**. 글라스 사진동기화(수초 지연)보다 빠르고, 전체 사진접근 권한 불필요(카메라 권한만) → **심사·UX 모두 유리**. Phase 16 파이프라인 재사용 가능.

### 5.5 Live 음성 모드(저지연 대화)

이미 바지-인·자동 재청취 골격은 있음(T-118). 강화:
- 문장 경계 도착 즉시 TTS 시작(전체 대기 X) — 체감 지연 ↓.
- 발화 중 끼어들기(바지-인) 안정화, VAD 침묵 임계 사용자 조정.
- "Live" UI: 파형 + 상태(듣는중/생각중/말하는중)를 풀스크린으로.

### 5.6 실시간 푸시(APNs) — 폴링 대체

현재 폴링·BGAppRefresh의 즉시성 한계를 해결. Bridge가 기기 토큰을 보관하고 **칸반 done/blocked·크론 완료·긴 응답 완료·Live Activity 갱신**을 APNs로 발사. 
- 비용: APNs 인증키 + Bridge에 푸시 발신 로직(stdlib HTTP/2 부담 → 작은 헬퍼). 사설망 철학과 충돌 없음(토큰만 Apple 경유, 내용 최소화 가능).
- 효과: **백그라운드에서도 제때 알림** + Live Activity 원격갱신 → 5.1의 완성도 급상승.

### 5.7 그 밖의 모바일 네이티브 카드

- **공유/액션 익스텐션** — 타 앱의 선택 텍스트·URL·이미지를 "Hermes 프로필로 보내기". 모바일에서 가장 자주 쓰일 진입점.
- **App Intents 확장**(T-132 기반) — "헤르메스에게 X 물어봐" 파라미터 인텐트가 **결과를 Siri로 바로 응답**(앱 미진입).
- **Apple Watch 컴패니언** — 손목에서 음성 캡처·칸반 글랜스·알림.
- **Spotlight 색인** — 세션 제목/내용 시스템 검색.
- **위젯 상호작용**(T-135 기반) — 홈 위젯에서 실행중 태스크·최근 세션 바로가기.

## 6. 강화 방안 로드맵 (우선순위)

> 기준: 가치 × (심사 안전성) ÷ 공수. **심사 통과가 먼저** — 그 전엔 신규 기능 동결 권장.

### 0순위 — 심사 통과 (지금)
- 리뷰노트에 **데모 접속법/데모영상/데모계정** 첨부, 미검증 기능 **숨김/비활성**, 권한 설명문 점검. (코드 변경 최소, §3.2 표 기준)

### 1순위 — 부채 정리 (심사 직후, 신규 0)
- **Phase 15~20 맥 빌드 + 실기기 검증** 일괄 — 특히 음성 핸즈프리(T-117~122)·세션 핀(T-147)·크론/프로필(T-138~146). 새 코드 아님, **이미 쓴 코드를 가치로 전환**.
- Bridge 재배포 누락 점검(HANDOFF §2.5) — 신규 엔드포인트 404 방지.

### 2순위 — 모바일 차별화 1탄 (낮은 심사리스크·높은 가치)
1. **Live Activity / 다이내믹 아일랜드**(5.1) — 칸반·토론·음성 상태. ActivityKit 내장, 명확한 가치.
2. **공유 익스텐션**(5.7) — 진입점 확대. 표준 API.
3. **카메라 라이브 "보면서 묻기"**(5.4) — 카메라 권한만, Phase16 재사용.
4. **AirPods 머리제스처·귀감지**(5.2) — 음성 UX 품질 도약.

### 3순위 — 실시간성 (인프라 필요)
5. **APNs 푸시**(5.6) — 폴링 대체 + Live Activity 원격갱신. Bridge 발신 로직 + 인증키 필요(공수 중).
6. **비동기 실행 화면 `/v1/runs`**(4-①) + **라이브 로그**(4-④) — 에이전트 작업 가시화.

### 4순위 — 패리티 마감
7. 툴셋 토글(T-097/098), 파일 편집(4-③), 칸반 events 타임라인(T-096).
8. App Intents 결과응답 확장, Apple Watch, Spotlight.

## 7. 즉시 권장 액션 3가지

1. **심사 리뷰노트 보강** — Tailscale 백엔드 시연 불가가 1순위 거절사유. 데모 경로/영상/접속 안내를 즉시 준비(코드 무관, 오늘 가능).
2. **Phase 15~20 검증 스프린트 계획** — 맥 빌드 1회 + 실기기 체크리스트(TASKS Phase 15/16/17 절에 이미 작성됨) 소화로 NEEDS-BUILD 부채를 DONE으로. **신규 개발 전 필수**.
3. **2순위 1탄 중 Live Activity를 다음 피처로 확정** — 모바일 차별화가 가장 크고 심사 안전. `superpowers:brainstorming`으로 범위(어떤 활동을 라이브로 띄울지)부터 좁히고 착수.
